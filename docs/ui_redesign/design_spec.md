# GIM18 — спецификация редизайна интерфейса

Статус: дизайн-цикл (без реализации). Сопутствующие файлы: [`research_references.md`](research_references.md), [`client_paths.md`](client_paths.md).

Цель цикла — спроектировать эргономичный, «нативный» интерфейс поверх **существующей** машинерии GIM18 для **ЛПР** (а не аналитика), с опорой на LLM-сценарии, где модель играет за страну. Бэкенд не переписываем; UI скрывает рантайм-контракт, но оставляет его прослеживаемым.

Аудитория: двуязычная (RU primary / EN switch). Решения цикла: персона = **смещение компиляции доктрины** (не override); персоны = **нейтральные архетипы**.

---

## 1. Принципы (из исследования референсов)

Ранжировано; каждый — с опорой на референс (детали в `research_references.md`).

1. **Один экран, одна цифра-вердикт.** Сверху — человеко-читаемый вывод + единый индекс критичности. *En-ROADS, NYT Needle.*
2. **Манипулируй-и-смотри, без церемонии запуска.** Минимум полей до результата; пресеты и разумные дефолты вместо конфигурации. *En-ROADS (нет кнопки Run), Epidemic Calculator.*
3. **Всегда «текущее против базовой линии».** Любой график и любая доктрина показывается как изменение относительно базы, не в вакууме. *En-ROADS (две линии).* В GIM18 это уже есть в данных: `evaluation.json` хранит baseline + policy траектории.
4. **Конкретное прежде абстрактного.** Вход — через осязаемое последствие/сценарий, не через параметры. *Dollar Street, Nicky Case explorables.*
5. **Прогрессивное раскрытие.** Простая поверхность по умолчанию, «Advanced» прячет рычаги/CSV/флаги. *PolicyEngine, En-ROADS.*
6. **Гид сначала, песочница потом.** Ведущие пути — направляемые; «Экспертный режим» — последним. *En-ROADS guided assignments.*
7. **Вероятность словами + спокойная неопределённость.** «Скорее да, чем нет»; полосы/банды, **без нервной анимации** (провал дёргающейся Needle-2016). *NYT.*
8. **Объяснение — по запросу (pull).** Раскрыть-почему вместо стены текста. *PolicyEngine «explain this number».*
9. **Сценарий/персона — объект первого класса.** Сохраняется, переоткрывается, шарится как карточка/ссылка с точным состоянием.
10. **Сдержанная плотность (анти-Bloomberg).** Около-чёрный фон, одна цветовая система, насыщенный цвет — только на вердикте и идентичности актора.

## 2. Сдвиг информационной архитектуры

Текущий прототип организован вокруг **команд CLI** (`Simulation Modes / Game / Analytics`) — обнажает рантайм. Новый — вокруг **намерения**:

```
Главная (выбор пути)
├─ ▶ Играть за страну   → Setup персоны → Прогон → Ситуационная комната   (флагман)
├─ ⚡ Что если…          → Карта пресет-шоков → Прогон → Ситуационная комната
├─ ⚖ Сравнить            → 2–3 прогона рядом (diff исходов/рисков)
└─ ⚙ Экспертный режим    → весь нынешний пульт (рычаги, CSV, флаги) — pro mode, ничего не теряем
```

Карта экранов: `Home → Setup → Running → SituationRoom (→ Compare)`; `Settings`, `Docs`, `Recent runs` — глобальные.

## 4. Модель персоны (ядро дизайна)

Решение: **персона смещает компиляцию доктрины**, не заменяет её. Привязка к коду:

- Сейчас `CompiledLLMPolicyManager` (`gim/compiled_policy.py`) компилирует **доктрину** — вектор 9 латентных предпочтений `[0,1]` (`escalation_bias`, `trade_openness`, `sanctions_tolerance`, `mediation_openness`, `domestic_priority`, `reserve_protection`, `military_readiness`, `finance_defensiveness`, `climate_pragmatism`) из состояния страны через `COMPILED_DOCTRINE_PROMPT`; затем `_action_from_doctrine` детерминированно разворачивает её в годовые рычаги.
- **Персона** = структурированный блок, который добавляется в контекст компиляции (`_context_payload` + промпт), смещая выводимый вектор. Доктрина по-прежнему отражает реальное состояние страны — персона лишь сдвигает приоритеты.
- **Доктрина в UI — read-only прогноз «база → сдвиг»**: компилируем дважды (без персоны = база; с персоной = сдвиг) и показываем дельту. Это реализует принцип 3 и честно показывает «что делает персона».

### 4.1 Каталог архетипов (нейтральные, не привязаны к живым людям)

| Архетип | Сдвиг доктрины (направление) | Иконка |
|---|---|---|
| Ястреб-протекционист | escalation↑, sanctions_tolerance↑, trade_openness↓, mediation↓ | `ti-flame` |
| Голубь | mediation↑, escalation↓, trade_openness↑ | `ti-feather` |
| Технократ | нейтрально к базе, finance_defensiveness↑, climate_pragmatism↑ | `ti-cpu` |
| Своя (custom) | задаётся декларацией | `ti-plus` |

Опционально (компромисс из вопроса о подаче): у пресета может быть подпись-пример («в духе торговых войн 2018»), без моделирования конкретной личности.

### 4.2 Поля персоны (схема в духе WarAgent, прогрессивное раскрытие)

- **Установочная декларация** (видима, редактируема) — 1–2 фразы, задают «голос» и смещают компиляцию.
- **Ключевая цель/политика** — одной строкой (попадает в `hybrid --intent ACTOR=...`).
- **Advanced (скрыто):** сырой системный промпт, явные нудлы по измерениям доктрины, правила/гардрейлы, секретные цели.

### 4.3 Задекларированная позиция в ходе прогона (из CICERO)

Каждый ИИ-актор перед годовым ходом **объявляет позицию** («давлю на Китай по торговле, ищу сделку»), и его действия согласованы с ней. В UI — лента «ходов» с позицией над действием. Источник в данных: `hybrid_result.json` (compiled intents) + per-actor action CSV.

### 4.4 Фон остальных акторов

Непрослеживаемые игроки идут на `--background-policy compiled-llm` (или `llm`), т.е. та же доктринная компиляция без персоны. ЛПР видит лишь «12 стран — ИИ-автопилот».

## 5. Ключевые компоненты

- **Карточка актора/персоны** — флаг-код (US/CN/…) + архетип + тэглайн. Галерея, не одно поле-промпт.
- **Доктрина-превью** — 6–9 строк «база-маркер → fill-сдвиг» + дельта (mono). Read-only.
- **Прогноз исходов** — горизонтальные полосы вероятностей режимов риска (метеосводка), цвет = валентность (good/warn/bad). Источник: `evaluation.risk_probabilities`.
- **Индекс критичности** — кольцо-гейдж 0..1, цвет по порогу. Источник: `evaluation.criticality_score`.
- **Мини-траектории** — спарклайны ВВП (policy vs baseline), соц. напряжённость, цены. Источник: `trajectory[*].agents`, `global_state.prices`.
- **Драйверы** — топ `evaluation.driver_scores`.
- **Трейс-строка** (mono, приглушённая) — точная CLI-команда / путь к `evaluation.json`. Честность + воспроизводимость.

## 6. Привязка экранов к бэкенду (что эмитит UI)

| Экран / путь | Команда |
|---|---|
| Играть за страну | `gim hybrid --tables "<country>" --intent "<country>=<goal>" --round-years <h> --background-policy compiled-llm --dashboard --brief` (+ persona-bias в контексте доктрины) |
| Что если… (пресет) | `gim question --template <preset> --actors ... --sim --dashboard --brief` |
| Что если… (свой вопрос) | `gim question --question "<free text>" --sim --dashboard --brief` (модель сама подбирает акторов/шаблон) |
| Сравнить | 2–3 прогона выше + diff `evaluation.json` |
| Экспертный режим | нынешний билдер `question / game / hybrid` со всеми флагами |
| Ситуационная комната | читает `run_manifest.json → evaluation.json / decision_brief.md` (эндпойнты `/api/run/<id>/analytics`, `/api/analytics/latest`) |

Новое для реализации (следующий цикл): persona-объект и его инъекция в `CompiledLLMPolicyManager`; эндпойнт persona-каталога; «база vs сдвиг» двойная компиляция для превью; лента задекларированных позиций.

## 7. Ограничения цикла

- Это **дизайн**: мокапы (inline + HTML) и клиентские пути. Код персон/LLM-акторов и нового UI — следующий цикл.
- Цифры в мокапах иллюстративные, не из прогона.
- Доктрина-превью «база→сдвиг» требует двойной компиляции — стоимость/латентность LLM нужно оценить при реализации (возможен кэш/эвристический предпросмотр).
- Архетипы и их сдвиги — стартовый набор; требуют калибровки против реальных прогонов, чтобы «характер» был различим в исходах.
